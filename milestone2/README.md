# Milestone 2 — Analysis Code, Figures and Artifacts

Companion package for **"AI-Driven Detection of Lateral Movement — Milestone 2"** (Steps 1–6).
Everything in the report is reproducible from these scripts. Paths: every script resolves the package root as the parent of `scripts/` (override with the environment variable `M2_ROOT`); the raw data goes under `<root>/data/` (paths at the top of `extract_lmd.py`, `extract_mordor.py`, `addenda_checks.py`) and steps 2–3 write `<root>/features/*.parquet` (≈50 MB, not shipped).

## Pipeline (run in this order)

| Step | Script | What it does | Output |
|---|---|---|---|
| 1 | `scripts/common_features.py` | Shared feature-engineering module: one function derives the 42-feature candidate pool (FEATURE_COLS / FAMILY are the single source of truth for counts) from a normalised intermediate event schema (temporal, velocity, direction-aware fan-out — outbound destinations from Initiated = true rows, inbound peers from SourceIp / Security client IpAddress — incl. inbound admin-port, graph (outbound out-degree, first host→destination edge), user, lineage incl. remote-exec-after-inbound, cmdline, credential, tool-transfer, auth/service, causal observed-modality indicators (running maximum per host)). Applies per-event-type field-applicability masking and treats the LMD placeholder string "0" as missing. Used identically for both datasets (Chapter 5 "unified schema"). | — |
| 2 | `scripts/extract_lmd.py` | Parses the raw labelled LMD-2023 CSV (`LMD-2023 [1.75M Elements][Labelled]checked.csv`), normalises it, builds features. Label: 0=Normal, 1=EoRS∪EoHT (`label_multi` keeps 0/1/2, carried through `build_features` so that it stays row-aligned after its sort). | `features/lmd_features.parquet`, `artifacts/lmd_address_kinds.json` |
| 3 | `scripts/extract_mordor.py` | Parses OTRF Mordor APT29 day-1 + day-2 host JSON, derives weak labels by process-provenance tracing (Sysmon EID1 tree, seeded by tool names, emulation-specific artefact names and PowerShell download/encode idioms — bare generic tokens such as `iex`, `webclient`, `-nop`, `hidden` are deliberately not used because they match iexplore.exe, the WebClient service host and ordinary admin scripts — then propagated to descendants; labels are provenance-only — no authentication-event rule, so Security-log features are not label-defining; note that Security-channel rows carry no ProcessGuid and are therefore always background under these labels). Event IDs are kept only for the Sysmon and Security channels and System 7045; every other channel is mapped to -1 ("other") because event numbers are provider-specific (System 1/3/6/10–14/16/18/20/25 and TerminalServices 21–24 — 78 rows — would otherwise collide with Sysmon IDs). Builds features. | `features/mordor_features.parquet`, `artifacts/mordor_labels.json` (seed / process / row counts quoted in §3.1.1), `artifacts/mordor_address_kinds.json` |
| 4 | `scripts/eda_stats.py` | Chapter 3, on ALL rows: attack-positive AUC / Cliff's δ, Cramér's V (χ² or Fisher's exact), plug-in mutual information in bits with an automated `0 ≤ MI ≤ H(Y)` assertion, JS divergence, Holm-corrected p; Spearman redundancy; zero-variance per dataset. | `artifacts/eda_stats_{LMD,Mordor}.csv`, `eda_meta_*.json`, `corr_lmd_spearman.csv`, `redundancy.json` |
| 5 | `scripts/ranking.py` | Chapter 4: regularised Random Forest MDI + permutation importance + LightGBM gain on BOTH datasets; random vs grouped (host×10-min) splits; ablations without time features and (Mordor) without label-seed-overlapping features; cross-dataset rank comparison on the composite basis (mean of RF-MDI share and LightGBM-gain share, average ranks for ties; `python scripts/ranking.py --cross-only` recomputes it from the saved per-dataset CSVs). | `artifacts/ranking_{LMD,Mordor,cross}.csv`, `ranking_summary.json` |
| 6 | `scripts/split_audit.py` | Split audit (random / host×10-min / host×day / chronological 70/30) with exact row and positive counts and test prevalence, RF without absolute-time features (pool minus the five time features); Mordor reduced-feature consistency check (pool minus the lineage + command-line families, the time features and the PID control — Table 8, ‡ rows). | `artifacts/split_audit.json` |
| 7 | `scripts/confound_diag.py` | Within-modality (EID 3 only) control for the fan-out / inbound features (Chapter 4, Surprise 3); also the scale-shift medians / 90th percentiles used in §5.2. | `artifacts/confound_diag.json`, `artifacts/scale_shift.json` |
| 8 | `scripts/figures.py` | All eleven report figures (Figures 10–11 = complete candidate-pool evidence) (colour-blind-safe palette validated for CVD). | `figures/fig01…fig11.png`, `figures/dims.json` (pixel sizes for the layout), `artifacts/mordor_bins.json` (5-minute-bin interleaving count) |
| 9 | `scripts/scaling_audit.py` | Chapter 5.3: RobustScaler (median/IQR) fitted on the training rows of the host × day split for every continuous schema feature, applied to held-out rows; cross-dataset fit check. | `artifacts/scaling_audit.json` |
| 10 | `scripts/export_tables.py` | Exports every rendered table row and the code-derived counts (pool size, unified schema size, one-hot dimension). | `artifacts/report_tables.json` |
| 11 | `scripts/addenda_checks.py` | Four data checks quoted in §1.3, §3.2–3.3, Table 4 and Table 10: (a) every `.255` address in LMD-2023 with its row counts and whether its /24 prefix holds a monitored host's own interface (the broadcast rule is exact for this capture: nine 192.168.x.0/24 networks, 10.0.1.0/24 and the link-local 169.254.255.255; Mordor's two .255 addresses are checked the same way); (b) Mordor rows whose EventID lies in the Sysmon numeric range but was logged by another channel (78 rows, 0.01% — the rows that per-channel interpretation keeps out of the Sysmon categories); (c) per Mordor host, the rows/seconds before the first Security-channel event and the first Sysmon EID 3 (the window in which `sec_observed` / `net_observed` = 0 means "not yet observed"). | `artifacts/addenda.json` |
| 12 | `scripts/build_report.js` | Generates the Word report (docx-js) from `artifacts/report_tables.json` (which embeds the split-audit rows), `confound_diag.json`, `scale_shift.json`, `addenda.json`, `eda_stats_Mordor.csv` and the figures (`NODE_PATH=$(npm root -g) node scripts/build_report.js`; PDF via LibreOffice). | `Milestone2_Report.docx` |

The within-modality (EID 3 only) control is recorded in `artifacts/confound_diag.json`, the scale-shift quantiles in `artifacts/scale_shift.json`, the Mordor 5-minute-bin interleaving count in `artifacts/mordor_bins.json`; `artifacts/report_tables.json` holds every table row and every derived statistic quoted in the prose exactly as rendered; the generator types only the dataset facts of Table 4 (verified against the raw files), the paper facts of Chapter 2 / §6.2 and the model settings; `artifacts/nice_names.json` (hand-maintained) maps feature names to display names; `figures/dims.json` records figure pixel sizes for the layout. `scripts/confound_diag.py` → `artifacts/confound_diag.json`, `artifacts/scale_shift.json`.

## Environment
Python 3, pandas 3.0, NumPy 2.4, scikit-learn 1.8, scipy 1.17, LightGBM 4.7, matplotlib 3.10, pyarrow; Node.js + `docx` for the report.

## Notes
* Feature engineering and all Chapter-3 statistics run on the complete data; the tree rankings and split audit use a 400k-row sample that contains every LMD attack row.
* Rolling/graph features are trailing (past-only) windows per host.
* Mordor labels are *weak* (provenance-derived) and are seeded from Image, ParentImage and CommandLine, the input fields of the lineage and command-line features; Mordor scores are label-consistency checks, not detection performance. The reduced-feature check in `split_audit.py` removes both families entirely (including integrity_high, which reads IntegrityLevel).
* Sampling for the tree rankings and the split audit: every positive row kept, negatives sampled uniformly to 400,000 rows (seed 42); test prevalence is therefore higher than in the full data and is reported next to every PR-AUC.
* LMD-2023 benign and attack rows were captured in disjoint time periods (see Chapter 3); no within-LMD split measures generalisation.
